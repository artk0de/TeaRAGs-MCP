# H6: eliminate a false hook denial

Tracker: tea-rags-mcp-eqli3. Scope is the Codex one-file-read hook generated by
scripts/gen-harness-codex.ts. The old inline-interpreter heuristic counts every
quoted Markdown pathname whenever any read marker occurs, including a distinct
write destination. This creates an avoidable failed tool call and recovery turn.

Keep the existing conservative literal scan. Parse Python-compatible syntax
without executing it, then subtract only literal occurrences proved to be direct
Path.write_text/write_bytes destinations or literal open destinations in w/a/x
modes without '+'. Do not subtract variable bindings or other occurrences of the
same pathname; do not discard nested reads used to compute a destination.
Unparseable interpreter code and unrecognized forms retain the old fallback.
This is a heuristic output guard, not a Python dataflow analyzer or security
sandbox.

RED: a new runtime unit reproduction observed exit 2 instead of 0 for the
single-read/different-write command. GREEN: the exact immutable test includes
Path writes, open positional/keyword modes, two genuine reads plus a write,
read/write mode w+, and a filename also read through a variable. All 63 relevant
generator tests pass after the implementation; no full repository suite run.

Behavioral gate: independent native actors with sealed shipped plugin snapshots,
gpt-6.1-sol/medium, n=1 per case/policy. H01 exercises the natural native
PreToolUse injection on one read plus a write; H02 invokes that same installed
script with synthetic two-read JSON, without reading the underlying files. H02
is a shipped-script control, not a claim that a model attempted a prohibited
multi-file read. Record this limitation. Baseline is immutable installed 0.55.6;
candidate is 0.55.7 with the hook change and the original H2 Explore body.
Expected baseline H01 denial remains retained as FAIL, never silently retried.

This fix removes a known failure path, not a claim that all semantic search
questions are faster than B. H4/H5 remain rejected policies. Future retrieval
work must preserve representative chunk locators while diversifying files:
VectorSearchStrategy already uses grouped Qdrant reads for file mode, but
BaseExploreStrategy.shapeFileLevel deliberately strips chunk-specific fields.
Even explicit locator fields currently produce fieldsWarning. A separate,
backward-compatible contract needs tests before changing that behavior.
