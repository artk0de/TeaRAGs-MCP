### Current-arm failure (R1, R2): the pick rule

Both runs chose, for computeTotal,
`164d69a fix(billing): skip zero-quantity lines — bug-fix`,
`7502e4c fix(billing): round totals… — bug-fix`, then
`5269882 feat(billing): support credit notes` — skipping the newest commit
`8066526 fix typo in rounding comment`. Tagging and order were otherwise right
(processBatch and reconcile picks exact, `fixes #42` and `hotfix:` tagged,
`feat`/`chore` untagged). The line at fault, `references/enrich.md` step 7:

> Pick ≤3 per row: bug-fix commits first, then newest. Bug-fix = subject matches
> … NOT when it fixes typo, lint, format, style, whitespace, imports, tests,
> specs, flaky, ci, conflicts, or review.

The NOT-list defines the bug-fix TAG, but sits in the pick sentence's paragraph;
the model applied it to selection and dropped the cosmetic commit. Two runs,
same reading — a text fork, not noise. The skill must say which it wants: either
"cosmetic commits stay eligible for 'then newest', untagged" or "skip cosmetic
commits when filling the remaining slots" (the latter arguably gives better
evidence; then this suite's `PICKS` changes, not the skill).
