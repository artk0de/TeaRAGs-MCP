# Q01/Q05 saved-trace audit

Two confirmed levers: **argument-schema-only metadata discovery** and **a conditional search banner instead of a mandatory graph step**. Root owns both fixes and their behavioral cases. This audit read saved native events and sanitized questions only; it ran no model/corpus queries and did not inspect encrypted reasoning.

|---|---:|---:|

Counts do not establish that every additional call is avoidable. Q01 is a broad ports/registration/capability/data-model question; migration/schema and service reads can be justified. New Q05 obtains useful MIME-classification evidence beyond the old answer.

## 1. Metadata diet: confirmed duplicated delivered context

Q01 wrapper `ctc_01ea513854152a31016ae4c60ceb6881919bfff59d2ff240d5` selects complete descriptions for find_symbol/get_callees/get_callers/semantic_search, alongside explore instructions. Actual delivered output `ctco_01a18da5-afc6-7e20-a9ce-995587a2c034` is **39,617 characters and already truncated**. It still contains three shared-core occurrences with an identical 3,033-character prefix: **at least 6,066 duplicated delivered characters**. These figures use the actual actor-visible custom output, not the larger untruncated buffer.

A working old-trace recipe already exists: wrapper `ctc_071bb8788ac12550016ae492c9aff8819193a02d4f5e1ccb69` slices selected descriptions at `exec tool declaration:`. Proposed change: names for discovery; only the selected argument declaration when syntax is missing, retaining unique parameter documentation. Do not remove necessary schema inspection or claim an unmeasured token/latency gain.

Behavior pair: a known method/body gap with the needed schema already retained must obtain the actual body without repeating shared instructions. Control removes the schema: a single necessary argument-declaration lookup and successful body retrieval must remain valid. Full raw scenario inputs and external criteria are in the JSON.

## 2. Search banner: confirmed source-complete graph detour

The exact `structuredContent.banner` in both traces is:

> ↳ Anchor = the row whose symbol names the asked behaviour (any row, not row 1) → get_callees(symbolId: <anchor>, depth: 2) → ONE find_symbol(symbols:[needed ids]).

Q01 delivers complete registry.rb lines 1–133 in wrapper `ctc_01ea513854152a31016ae4c6194c8c8191a3ca887f964ce4ce`, alongside metadata carrying that banner. `exec-28f3a799-bbad-464f-9c33-1d547d7502f1` then returns noEdges for adapter_for_provider. Its subsequent literal filename search finds real port services, so that search itself is not prohibited by this audit.

Q05 is the sharper case: `exec-5d3e84e7-bcad-4c96-94ad-2a4f9af55ccf` already delivers **both** previewable? and file_extension bodies. `exec-a8c15361-6227-41cf-a100-72ee23656aeb` then repeats the known previewable? → file_extension edge and adds an unrelated dynamic Twilio OptionalValue#blank? edge. Neither contributes a new requested implementation fact. Old Q05 answers the storage/preview question without any graph probe; old Q01 also has one graph call, so this is not presented as explaining its entire count regression.

Fix the banner producer, rather than adding another unconditional prompt clause: direct missing-body reads for definitions; reuse complete current bodies; graph only when the question or an identified evidence gap needs flow/impact. Behavior pair: a source-complete previewability question plus a companion search result processed through the real producer should answer without a graph detour. Control explicitly asks for two-level flow or supplies an unresolved helper; preserve necessary graph/missing-body retrieval.

## Observations excluded from new policy recommendations

Q01 batches directory paths in symbols[], gets explicit directory/missing, then retries via relativePath. The core already forbids that shape, so another clause is not proposed. Q05's second graph imports call has a real unresolved frontend constant gap, unlike the clearly redundant backend probe; no blanket graph ban is justified. No additional duplicate body/skill read is claimed. An outline or budgeted-out file body is not counted as already read. Recommendations and paired control conditions are recorded in `new-levers-q01-q05.json`; no production or historical artifacts were changed.
