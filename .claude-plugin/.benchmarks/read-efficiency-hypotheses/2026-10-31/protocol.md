# Native read efficiency hypothesis protocol

Freeze this protocol, grading, raw cases, runner/backend/collector, dependencies and every installed plugin file before actors. Raw requests and fixtures remain separate from grading. No expected answers, old actor responses or grading files may be accessible to actors. This is a focused synthetic suite derived from held source evidence, not a replay of the original context.

The fixed condition is gpt-6.1-sol / medium, n=1 for each selected case/variant, at most two concurrent actors. Service caching cannot be disabled: report each response's inputTokens/cachedInputTokens and initial response cache. Fresh homes/threads, memories=false, no copied local caches/history. Capture native raw response events, final answer, call arguments/results, usage, thread status and fixture audit. Never substitute child tool count for native MODEL responses, including the final response.

Preparation requires a named source snapshot from the parent and ready raw fixtures. Install the shipped plugin through native marketplace/plugin commands. Preserve exact source/version fingerprints and dynamic file inventory, not a historical hardcoded file count. Generated .mcp.json must exist. Prove zero turns, exactly 14 trusted shipped hooks, 18 enabled shipped skills, connected fixture MCP and denial of controller/gold/home paths. A proof thread is ephemeral; each production actor starts with no turns. Launch requires explicit parent GO and --rootgo; preparation is model-free.

Correctness: review actual final claims against source that was delivered or already held in equivalent complete form. Metadata, outlines, headers and budget-truncated excerpts do not prove omitted implementation. Mixed outline/body results retain each complete body. Every required source unit identifies task-relevant source only; nearby helpers are optional. Automatic regex signals support semantic review; they never override it. Unsupported claims, missing requested facts or invalid absence claims fail correctness. A factual response may cite previously held source without new reads. User discussion can supply intent but is not implementation evidence.

Efficiency: evaluate only after factual review. Record native response count, evidence availability at each response and avoidable rereads/discovery. Different valid source acquisition routes may pass; exact incidental helper reads, tool names/counts or one prescribed wording are not correctness requirements. Classify held body reuse, known-file direct content retrieval, batching independent ready content, bounded configuration reads and stopping when sufficient separately. Class/header/outline/budget/changed-file controls require source covering missing facts; dependent new locators allow necessary discovery; complete absence needs a complete scoped search. A fresh new read is allowed where held content does not cover the claim. No broad speed or reliability conclusions from n=1.

Cases and grading must be frozen before any actor. Run only selected affected cases and nearby controls; no full39 benchmark or corpus/index mutation. Preserve every failed/unrun attempt and report it OPEN. Corrections require a new immutable attempt/variant path with relevant rerun cases. Never silently rerun, overwrite verdicts or move criteria to pass. Semantic judgments must identify claim/source evidence and material limitations.

Hook ledger shape is a separate instrumentation question. Inspect native hook events first. Do not invent adapter input JSON. If actual Pre/PostToolUse payloads are unavailable, request parent GO for one separately fingerprinted passive diagnostic installed-wrapper capture, logging stdin unchanged outside actor-readable roots and delegating to the shipped hook. Such a capture is not efficacy evidence.
