# tea-rags for ZCode

GENERATED by `scripts/gen-harness-zcode.ts` from `plugins/tea-rags/` and
`plugins/dinopowers/` — do not edit. tea-rags 0.55.11, dinopowers 0.25.3.

Rendered from `plugins/**/skills/**`, `plugins/tea-rags/rules/core.md` and the
plugin version. Try an edit locally with `npm run gen:harness-zcode`; the
release regenerates this package and commits it.

## Layout

This directory is a ZCode marketplace root: add it (**Plugin Management →
Discover → +**) as a local directory, then install `tea-rags` (and `dinopowers`,
`tea-rags-setup` as needed) from it.

- `marketplace.json` — the marketplace catalog; `source` = `./<plugin>`,
  `displayName` = the brand spelling (TeaRAGs / Dinopowers / TeaRAGs Setup — the
  UI shows and searches it), `icon` = the committed `assets/icons/<plugin>.png`
  over `raw.githubusercontent.com` (the app draws only `https://` icons; the
  same PNG also ships as `<plugin>/icon.png` so the package stays
  self-contained).
- `tea-rags/.zcode-plugin/plugin.json` — manifest: `skills`, `hooks`,
  `mcpServers`.
- `tea-rags/.mcp.json` — stdio server `tea-rags server`, auto-connected with the
  plugin.
- `tea-rags/hooks/hooks.json` — the wiring, ZCode's seven events only:
  SessionStart `${CLAUDE_PLUGIN_ROOT}/scripts/session-rules.sh` (core rules as
  additionalContext — ZCode parses hook stdout as JSON under a strict schema, so
  the Claude plugin's plain-text SessionStart output is wrapped), then
  `session-digest.sh` (`tea-rags prime` + the stale-build warning), then the
  read-ledger reset; UserPromptSubmit `turn-routing.sh --harness zcode`,
  `search-drift.sh --harness zcode` and the ledger (per-turn routing re-inject,
  drift counter reset, read steering); PreToolUse (`Grep|Bash`)
  `search-drift.sh` — `permissionDecision: "deny"` once after 3 concept-shaped
  text searches with no tea-rags call (one deny per 120 s; literal searches and
  config / spec / migration paths neutral; reads never denied); PreToolUse
  (`Read|Bash` | `mcp__*tea-rags*__find_symbol`) and PostToolUse the ledger;
  PostToolUse (`Bash`) `cleanup-clone.sh` (worktree-clone cleanup, side effect
  only); PreToolUse (`Agent|Task`) `subagent-context.sh` — **ZCode has no
  SubagentStart event**, so the subagent search block (Claude Code's
  `enforce-tearags-search.sh` payload) rides the Agent tool's PreToolUse
  additionalContext; forwarding into the subagent's own context is UNVERIFIED in
  a live install — MANUAL-TEST.md check 6.
- `tea-rags/skills/` — every user-invocable tea-rags skill plus each internal
  skill a shipped skill names.
- `tea-rags/repair/`, `tea-rags/rules/` — plugin files the skills link to by
  relative path.
- `dinopowers/` — the wrappers as `skills/dino-<s>/` (clear of the superpowers
  skills they wrap; not bundled — https://github.com/obra/superpowers), routing
  tables at SessionStart and subagent dispatch.
- `tea-rags-setup/` — the install and tune skills plus the Node helpers they
  run; no hooks, no MCP.

- `tea-rags/scripts/session-rules.sh` — SessionStart: `rules/core.md` (through
  `inject-rules.sh`) as `additionalContext`.

## Install

1. Build and link the CLI: `npm run build && npm link` (or install the published
   `tea-rags` globally).
2. Easiest — the setup wizard: add this directory as the tea-rags marketplace,
   install the setup plugin, then run the `tea-rags-setup:install` skill in a
   ZCode session (it detects the zcode host and finishes everything — tea-rags
   plugin + MCP, registration, first index):

   ```bash
   zcode plugins marketplace add "$(npm root -g)/tea-rags/harness/zcode"   # or <repo>/harness/zcode
   zcode plugins install tea-rags-setup@tea-rags
   ```

3. Manual alternative — install the plugins directly (UI: **Plugin Management →
   Discover → +**, or CLI), from the package's own copy so the marketplace
   always serves the installed client's release:

   ```bash
   zcode plugins install tea-rags@tea-rags        # + dinopowers@tea-rags as needed
   ```

4. Review the plugin's hooks in its detail view (Settings → Plugin Management →
   tea-rags).
5. Development build instead of the global binary: in the installed `.mcp.json`
   set `"command": "node", "args": ["<repo>/build/index.js"]`.
6. A workspace `tea-rags` server (`.zcode/config.json` → `mcp.servers`)
   overrides the plugin's; both auto-connect.

## Updates

`tea-rags update` — manual and background alike — brings every installed
`*@tea-rags` ZCode plugin to the installed client's release through this
marketplace: it refreshes the catalog, then updates a plugin only when
`installed < catalog ≤ client` — never past the client, never a downgrade. A
local tea-rags marketplace that is not the package's own `harness/zcode` is a
developer checkout and is left alone. The ZCode CLI is found on
`$TEA_RAGS_ZCODE_CLI`, `PATH`, or the macOS app bundle
(`/Applications/ZCode.app/Contents/Resources/glm/zcode.cjs`).

## Transform rules

Claude Code dialect kept where ZCode matches it (Skill tool, `tea-rags:<s>`
qualified mentions, Read tool, `mcp__tea-rags__<tool>`, AskUserQuestion);
`default code search tool` → `Bash rg` (ZCode sessions ship no Grep/Glob tool;
folded literals `Bash rg "<X>" <dir>`); `$CLAUDE_PROJECT_DIR` → `$PWD`;
`SubagentStart` → the subagent dispatch hook. `tea-rags://` resources: ZCode
exposes no model-side resource tool — the sources' inline fallback
`tea-rags resource <uri>` (Bash) is the route.

## Facts (zcode.cjs bundle + zcode-guide plugin, 2026-11-09)

- Manifest `.zcode-plugin/plugin.json` (`.claude-plugin/`/`.codex-plugin/` also
  recognized); `name` must match `^[a-z0-9][a-z0-9._-]{0,127}$`; component
  fields `commands`, `skills`, `hooks`, `mcpServers`, `agents` (recorded, not
  executed).
- Hooks: exactly seven events — `SessionStart`, `UserPromptSubmit`,
  `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`,
  `Stop`. **No `SubagentStart`.** Matcher = case-sensitive regex on the tool
  name; `Task` ↔ `Agent` are aliases. `timeout` in seconds; stdout parsed as
  JSON (strict schema, extra keys fail); `hookSpecificOutput.additionalContext`
  injects; exit 2 / `permissionDecision: "deny"` blocks PreToolUse;
  `updatedInput` supported on PreToolUse (unused here — parallel rewrites of the
  Agent prompt collide).
- MCP tools: `mcp__<server>__<tool>`, server name normalized by `[^a-zA-Z0-9_-]`
  → `_` (hyphens survive): `mcp__tea-rags__find_symbol`. Plugin `.mcp.json` via
  the manifest `mcpServers` field; workspace `.zcode/config.json` →
  `mcp.servers` overrides it; every scope auto-connects.
- No model-side MCP resource tool in the toolset (`ReadMcpResource` absent from
  zcode.cjs): resource reads go through the CLI fallback.
- Marketplace: local directory root with `marketplace.json` (or
  `.claude-plugin/marketplace.json`); `plugins[].source` a relative path string;
  `plugins[].displayName` free text over the lowercase id (id pattern
  `^[a-z0-9][a-z0-9._-]*$`; the UI shows and searches displayName, app bundle
  reads `listing?.displayName`); `plugins[].icon` any non-empty string in the
  catalog, but the app renderer draws only values starting with `https://` (its
  image validator, app bundle; six official plugins ship hardcoded data-URIs
  instead) — hence the raw.githubusercontent URLs and the pushed-to-main
  requirement; install/enable state in `~/.zcode/cli/config.json`.
- CLI (`zcode plugins`, verified 0.17.0): `list [--json] [--available]`,
  `install <p>[@<market>]`, `update <p>`, `marketplace add|remove|update`;
  `marketplace remove` KEEPS installed plugins; `plugins update` re-reads a
  directory marketplace by itself; the github source schema carries a `ref`, but
  `marketplace add` exposes no ref flag — hence the update guards above instead
  of a pin.
