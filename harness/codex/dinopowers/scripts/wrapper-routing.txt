## Dinopowers wrapper routing (MANDATORY — overrides direct superpowers:* invocation)

Subagent intents matching any row below MUST invoke the dinopowers wrapper BEFORE
(or instead of) the direct superpowers:* skill. The wrapper runs tea-rags
enrichment, then chains to superpowers internally.

| If your task is... | Invoke |
|---|---|
| Brainstorming a feature/refactor with a named code area | $dino-brainstorming |
| Authoring an implementation plan with a file list | $dino-writing-plans |
| Executing plan Tasks that modify files | $dino-executing-plans |
| Debugging a concrete symptom (error, stack trace, test failure) | $dino-systematic-debugging |
| Writing a failing test only — no production change in the task (TDD RED phase); finding / extracting test patterns or conventions | $dino-test-driven-development |
| Writing or changing production code outside a written plan (new function, behaviour change, perf rework) — DDG owns RED ($test-first, Step 6a) and GREEN; no separate TDD wrapper | $data-driven-generation |
| Claiming work complete / before commit / before PR | $dino-verification-before-completion |
| Agreeing/pushing back on a review comment that names a symbol | $dino-receiving-code-review |
| Composing a code review request with a diff | $dino-requesting-code-review |
| Finalizing a dev branch (merge/PR/cleanup decision) | $dino-finishing-a-development-branch |
| Creating a new dinopowers wrapper SKILL.md | $dino-writing-skills |

**Rules:**
- Do NOT invoke $brainstorming/writing-plans/executing-plans/systematic-debugging/test-driven-development/verification-before-completion/receiving-code-review/requesting-code-review/finishing-a-development-branch directly if the corresponding dinopowers:* wrapper applies. The wrapper calls superpowers internally with tea-rags context prepended.
- Stylistic / trivial cases (typos, one-word edits, listings, counting questions) bypass the wrapper — dinopowers descriptions explicitly exclude them.
- If a wrapper doesn't match your intent, invoke superpowers:* directly.
- These routing rules take priority over any skill that says "invoke $X" for a matching intent.
