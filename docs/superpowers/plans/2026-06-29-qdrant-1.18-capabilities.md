# Qdrant 1.18 Remaining Capabilities Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the remaining applicable Qdrant 1.18 server capabilities — strict-mode OOM guard (`max_resident_memory_percent`) + `search_max_batchsize`, low-memory daemon mode, bulk-reindex optimizer defer (`prevent_unoptimized`), and deep memory reporting in `get_index_status` (conditional on the 1.18 endpoint).

**Architecture:** Three new env vars extend `QdrantTuneConfig` (built on turbo's additions). Strict-mode config rides the same per-collection `create_collection`/`update_collection` path as turbo and reuses the startup-reconcile pattern (`reconcileStrictMode` beside `reconcileTurbo`). Low-memory injects on-disk `QDRANT__*` flags into the embedded daemon spawn env. Optimizer defer extends the existing `optimizer-lifecycle.ts`. Memory reporting wires `get_index_status` with a user/DEBUG split — or defers if the 1.18 memory endpoint is not cleanly available.

**Tech Stack:** TypeScript (ESM), vitest, `@qdrant/js-client-rest@1.18.0`, Zod, Qdrant `QDRANT__*` daemon env.

## Global Constraints

- Foundation + TurboQuant DONE (HEAD `b27250da`). Reuse: `QdrantTuneConfig.turboQuant`, `src/bootstrap/config/turbo-reconcile.ts` (`reconcileTurbo`, `TurboReconcileTarget`, `isTurboBits4`), `QdrantManager.updateCollectionQuantization` / `updateCollectionSparseConfig` (templates), `factory.ts#resolveInfrastructure` (already calls `reconcileTurbo`).

- Defaults: `QDRANT_MAX_RESIDENT_MEMORY_PERCENT` unset = guard OFF; `QDRANT_SEARCH_MAX_BATCHSIZE` unset = no cap; `QDRANT_LOW_MEMORY` default false.
