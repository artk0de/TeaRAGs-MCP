# Qdrant 1.18 Bump (Foundation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pin the embedded/required Qdrant server to 1.18.2 and the SDK to
1.18.0, keep the test suite green, document the BREAKING floor, and land the
standing release-notes env-reporting mechanism (F2).

**Architecture:** The bump is driven by one constant
(`.qdrant-required-version`) + one dependency (`@qdrant/js-client-rest`). No
runtime `src/` logic changes — `download.ts`/`qdrant-version.ts` only READ the
constant. Two test fixtures that hard-code the old version are rebound to the
live constant. The F2 release-pipeline change adds an `envChanges[]` section to
the changelog renderer so every future env addition/change surfaces in release
notes.

**Tech Stack:** TypeScript (ESM), vitest, `@qdrant/js-client-rest`, Node scripts
(`scripts/lib/render-changelog.js`), semantic-release.

## Global Constraints

- Embedded daemon server version + external-Qdrant minimum: **1.18.2** (single
  source of truth: `.qdrant-required-version`).
- SDK `@qdrant/js-client-rest`: **1.18.0**, exact pin (no caret).
- This is **BREAKING** for users on external Qdrant `< 1.18.2`
  (`QdrantVersionTooOldError` at startup) — commit footer required.
- No runtime `src/` edits. Test fixture updates must preserve asserted behaviour
  (not rewrite business logic).
- Commit convention: conventional commits, scoped; header ≤ 100 chars. Co-author
  footer per repo rule.
- Beads: epic `tea-rags-mcp-62zf`; each Task = one child task.

- [ ] **Step 3: Implement `renderEnvChanges` and splice it in.**

In `scripts/lib/render-changelog.js`, add the renderer (after `renderGroups`):

```js
// Environment-variable additions/changes for this release. Surfaced on BOTH
// artifacts so a user upgrading sees every new/changed knob with its default.
// `change` is "new" | "changed". Empty/absent → no section.
function renderEnvChanges(data) {
  const envs = data.envChanges || [];
  if (envs.length === 0) return "";
  const rows = envs
    .map(
      (e) =>
        `* \`${e.name}\` · ${escapeMentions(e.description)} · default: \`${e.default}\` (${e.change})`,
    )
    .join("\n");
  return `### 🔧 Environment Variables\n\n${rows}`;
}
```

Splice into `renderChangelogSection`:

```js
export function renderChangelogSection(data) {
  const env = renderEnvChanges(data);
  const envBlock = env ? `\n\n${env}` : "";
  return `${versionHeader(data)}\n\n${renderGroups(data)}${envBlock}\n`;
}
```

Splice into `renderReleaseNotes` (place the env section after the product
themes, before the Full Commits spoiler):

```js
export function renderReleaseNotes(data, contributors = []) {
  const body = renderGroups(data);
  const env = renderEnvChanges(data);
  const envBlock = env ? `\n\n${env}` : "";
  const commits = data.allCommits
    .map((c) => `- ${c.hash} ${escapeMentions(c.subject)}`)
    .join("\n");
  const spoiler = `<details>\n<summary>Full Commits</summary>\n\n${commits}\n\n</details>`;
  const credits = contributors.length
    ? `\n\n### 👥 Contributors\n\n${contributors.join(", ")}`
    : "";
  return `${versionHeader(data)}\n\n${body}${envBlock}\n\n${spoiler}${credits}\n`;
}
```
