The shared client has three layers: **HTTP errors**, **request metrics**, and **send-level refusal handling**.

**HTTP status → exception**

| HTTP status | Error |
|---|---|
| 400 | `BadRequestError` |
| 401 | `UnauthorizedError` |
| 403 | `ForbiddenError` |
| 404 | `NotFoundError` |
| 422 | `UnprocessableEntityError` |
| 423 | `LockedError` |
| 429 | `RateLimitedError` |
| 500 | `ServerError` |
| 503 | `ServiceUnavailableError` |
| Other ≥500 | `ServerError` |
| Other ≥400 | `RequestError` |

Statuses below 400 pass through. The adapter’s `vendor_error_class(body)` can override the status-derived class—for example, to identify quota exhaustion or insufficient scope. Errors retain the response **body, status code and headers**; their message comes from the vendor or an i18n fallback.

For API calls, `401` enters the authentication retry path and forces token refresh. Network failures become `NetworkError`; exhausted refresh-lock contention becomes `ConnectionBusyError`.

**Metrics**

| Metric under `tax_automations` | Tags | Meaning |
|---|---|---|
| `requests_duration` | `vendor`, `operation` | Duration in seconds |
| `failed_requests_total` | `vendor`, `operation`, `reason` | Failed attempts |
| `rate_limit_remaining` | `vendor`, `group` | `X-RateLimit-Remaining` |
| `rate_limit_reset_seconds` | `vendor`, `group` | Seconds until `X-RateLimit-Reset`, clamped to zero |

Operations are `api_request`, `connect`, `reconnect`, `token_refresh`, `token_revoke` and `upload_transfer`.

Failure metric reasons include `HTTP_ERROR: <status>`, `NETWORK_ERROR: <exception class>`, `LOCK_TIMEOUT` and `INVALID_GRANT`. These diagnostic labels differ from document failure reasons.

Rate-limit headers are recorded **before error middleware raises**, including on rejected responses. Authentication failures count per attempt. A refused refresh may be counted both as `token_refresh` and as the `api_request` needing it; do not sum those operations as unique failures.

Source: [metric definitions](/Users/Shared/nav-ab/repo-master/config/initializers/yabeda.rb:33).

**Terminal refusal → document failure reason**

[`RefusalsHelper`](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/refusals_helper.rb:9) maps:

| Refusal | Shared failure reason |
|---|---|
| `QuotaExceededError` | `exceeded` |
| `InsufficientScopeError` | `unauthorized` |
| `InvalidGrantError` | `unauthorized` |
| `UnauthorizedError` | `unauthorized` |
| Local `PolicyError` | `forbidden` |
| Other terminal refusals | `api_error` |

Other terminal refusals include HTTP forbidden/not-found/locked/bad-request/unprocessable errors and incomplete or expired upload targets. **Vendor HTTP 403 therefore maps to `api_error`, not local-policy `forbidden`.**

The helper fails affected uploads, restricted to the connection’s firm. Configuration/contract failures such as insufficient scope, malformed requests and incomplete targets are also reported to `ErrorReporter`. Policy and invalid-grant errors are re-raised for worker handling.

Transient errors—including `429`, network failures and server errors—follow retries. Instead’s export worker marks affected uploads `network_error` when nonterminal retries are exhausted. Processing failures use a separate adapter mapping; for example, Instead’s `password_required` becomes `encrypted`.
