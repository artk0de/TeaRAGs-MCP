Берём Instead за основу нейминга для **одинаковых ролей**:

| Instead | GruntWorx |
|---|---|
| `TaxPreparation::TaxAutomations::Instead` | `TaxPreparation::TaxAutomations::GruntWorx` |
| `Instead::Client` | `GruntWorx::Client` |
| `Instead::Connection` | `GruntWorx::Connection` |
| `Instead::ExportAsync` | `GruntWorx::ExportAsync` |
| `Instead::Mock::Adapter` | `GruntWorx::Mock::Adapter` |
| `Instead::Mock::Router` | `GruntWorx::Mock::Router` |
| `tax_automations_instead_*` | `tax_automations_gruntworx_*` |
| `tax_automations.instead` | `tax_automations.gruntworx` |
| `/webhooks/instead/events` | `/webhooks/gruntworx/events` |

По идентификаторам сохраняем различие:

- `uid` — существующий UUID объекта **TaxDome**: `contact.uid`, `client.uid`.
- `external_uuid` — идентификатор объекта **у провайдера**, как в Instead.
- `external_tenant_uuid` — идентификатор **аккаунта провайдера**, используемый для привязки фирмы.

Называть TD-идентификатор `external_uuid` ради похожести было бы неверно. Новые имена должны повторять Instead там, где совпадает назначение; названия специфичных сущностей GWX определяем по их роли, без автоматического копирования `Entity`.
