From the creation migrations plus subsequent changes, the current definitions are:

**`tax_preparation_tax_automations_instead_connections`**

| Index | Columns | Constraint |
|---|---|---|
| Primary key | `id` | Unique |
| `idx_ta_instead_connections_on_firm` | `firm_id` | Unique: **one connection per firm** |
| `idx_ta_instead_connections_on_refresh_expires_at` | `refresh_expires_at` | Partial: `WHERE status = 1` (`connected`); supports keep-alive selection |

**No database foreign keys.** `firm_id` deliberately references another cluster without an FK; creator is polymorphic (`creator_type`, `creator_id`).

The original unique `(firm_id, actor_type, actor_id)` index was renamed alongside actor → creator, then **removed** when uniqueness changed to firm-only. The added connection `external_uuid` has no index in these migrations.

**`tax_preparation_tax_automations_instead_documents`**

| Index | Columns | Constraint |
|---|---|---|
| Primary key | `id` | Unique |
| `idx_ta_instead_documents_on_entity` | `instead_entity_id` | Nonunique |
| `idx_ta_instead_documents_on_ta_document` | `tax_automation_document_id` | Unique |
| `idx_ta_instead_documents_on_firm_external` | `(firm_id, external_uuid)` | Unique, `WHERE external_uuid IS NOT NULL` |
| `idx_ta_instead_documents_on_external_uuid` | `external_uuid` | **Globally unique**, `WHERE external_uuid IS NOT NULL`; supports webhook lookup |

| Foreign key | References | Delete behavior |
|---|---|---|
| `tax_automation_document_id` | `tax_preparation_tax_automations_documents.id` | `ON DELETE CASCADE` |

`firm_id` is non-null but has **no FK or standalone index**; it leads the composite index above.
