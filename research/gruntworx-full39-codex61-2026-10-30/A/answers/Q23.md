For Instead, routing has two separate layers:

| Layer | Configuration | Behavior |
|---|---|---|
| Cluster forwarding | [`Middleware::Clusters::Webhooks::WEBHOOKS_MAP`](/Users/Shared/nav-ab/repo-master/lib/middleware/clusters/webhooks.rb:7) | `'/webhooks/instead' => :no_proxy` |
| Rails controller | [`config/routes/tax_preparation.rb`](/Users/Shared/nav-ab/repo-master/config/routes/tax_preparation.rb:752) | `POST /webhooks/instead/events` → `TaxPreparation::Webhooks::TaxAutomations::Instead::EventsController#create` |

**Cluster:** Instead deliveries stay on the cluster receiving the configured webhook URL. The webhook middleware does **not** broadcast them to other clusters or inspect the payload to choose one. `:no_proxy` passes the request into the local Rails application; it does not itself redirect to the US cluster.

**Controller:** The route sits under `AppDomainConstraint`, with the app host as its URL-generation default. `scope module: :tax_automations` changes the controller namespace **without adding `/tax_automations` to the URL**. The outer tax-preparation scope likewise contributes the module namespace.

After signature verification, local processing resolves the firm:

- Document events match the stored **entity UUID + file UUID**.
- Entity events match firms whose Instead account binding equals the event’s `firm` identifier.

That is **firm selection inside the receiving cluster**, not cross-cluster routing. A signed delivery with no local match is logged and acknowledged with `200`.
