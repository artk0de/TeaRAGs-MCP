The hierarchy is:

```text
Platform::Async::Operation::Worker
└─ TaxAutomations::OperationWorker
   └─ Instead::OperationWorker
      ├─ Instead::ExportOperationWorker
      │  ├─ Clients::CreateEntityWorker
      │  ├─ Documents::StartUploadWorker
      │  ├─ Documents::TransferBytesWorker
      │  └─ Documents::FinalizeUploadWorker
      └─ Webhooks::ProcessEventWorker
```

| Worker/base | Role |
|---|---|
| Shared `OperationWorker` | Default queue, 10 retries, common stop/retry rules and grant verification |
| `Instead::OperationWorker` | Instead throttle metadata: API group and connection ID |
| `Instead::ExportOperationWorker` | `step_only!`; adds file failure handling when a send step exhausts retries |
| Create entity / start upload / finalize | Export steps; high-priority **throttled** queue, using `entities` or `docs` budgets |
| Byte transfer | Also an export step, but high-priority **unthrottled** queue: it sends bytes to the bucket, not Instead’s API |
| Webhook worker | Inherits directly from `Instead::OperationWorker`; high-priority, no export-step failure callback |

Each concrete worker declares its own slug.

**When a send step exhausts retries**, [`ExportOperationWorker`](/Users/Shared/nav-ab/repo-master/app/workers/tax_preparation/tax_automations/instead/export_operation_worker.rb:8):

1. Runs inherited exhaustion handling to fail the operation.
2. Skips file updates if the operation is missing or canceled.
3. Reads affected IDs from `Args#tax_automation_document_ids`.
4. Maps terminal refusals through `RefusalsHelper`; otherwise uses `network_error`.
5. Calls shared `Documents::FailUpload`.

[`FailUpload`](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/documents/fail_upload.rb:41) moves eligible files to upload `failed` and processing `error`, or processing `exceeded` for quota exhaustion, then broadcasts after commit. Already `uploaded` or `failed` records retain their states.

An entity-creation failure can affect **all files in that send**; upload/transfer/finalize steps identify one file each. The webhook worker has no corresponding “fail these uploads” callback.
