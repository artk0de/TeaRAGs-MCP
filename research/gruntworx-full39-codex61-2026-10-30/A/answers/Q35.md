Tax automations can get **first and last names** through these CRM Public API calls:

| Call | Returned fields |
|---|---|
| `Crm::Api::Contact.find(firm:, user:, actor:, contact_id:)` | `data.first_name`, `data.last_name`, `data.contact_id` |
| `Crm::Api::Contact.list_by_ids(firm:, user:, actor:, contact_ids:)` | Each entry in `data.contacts` has `first_name`, `last_name`, `contact_id` |
| `Crm::Api::Contact.list_by_account(firm:, user:, actor:, account_id:)` | Only `contact_id`, `name`, `phone`; no separate name parts |

For one taxpayer:

```ruby
result = Crm::Api::Contact.find(
  firm: actor.firm,
  user: user,
  actor: actor,
  contact_id: tax_preparation.contact_id
)

# After checking success:
result.data.first_name
result.data.last_name
```

**The UUID is not currently exposed.** Although `contacts.uid` exists in the database, neither `find` nor `list_by_ids` includes it in its response mapping. The search of `app/services/crm/api` found no `uid`/`uuid` exposure.

For GWX, this is a CRM Public API contract gap: expose `uid` through the relevant contact lookup and its response contract, rather than reading the CRM model directly.
