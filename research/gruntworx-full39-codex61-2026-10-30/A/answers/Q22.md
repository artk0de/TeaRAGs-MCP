The two bases separate shared retry behavior from Instead-specific throttling.

| Concern | Shared `TaxAutomations::OperationWorker` | `Instead::OperationWorker` |
|---|---|---|
| Parent | `Platform::Async::Operation::Worker` | Shared operation worker |
| Default queue | `tax_preparation_tax_automations_default` | Inherited |
| Retries | `RETRY_ATTEMPTS = 10` | Inherited |
| Immediate stop | Missing record, policy denial, invalid grant → `:kill` | Inherited |
| HTTP 429 | Use `Retry-After`; otherwise normal retry scheduling | Inherited |
| Exhaustion | Fail the operation; invalid grant can schedule grant verification | Inherited |
| Throttle metadata | No provider-specific group/key | Supplies `rate_limit_group` and `connection_id` |
| Default API group | None | `rate_limit_group` returns `nil`, normalized to `default` |
| Slug | Does not declare one | Does not declare one; concrete workers declare their own |

The [shared base](/Users/Shared/nav-ab/repo-master/app/workers/tax_preparation/tax_automations/operation_worker.rb:9) also wraps subclass retry/exhaustion callbacks so they preserve inherited behavior. Ten retries are an **attempt budget**, not a wall-clock guarantee: throttle rescheduling resets the retry count.

The [Instead base](/Users/Shared/nav-ab/repo-master/app/workers/tax_preparation/tax_automations/instead/operation_worker.rb:8) provides throttle metadata but does **not itself activate throttling**. Concrete workers opt in. For example, [StartUploadWorker](/Users/Shared/nav-ab/repo-master/app/workers/tax_preparation/tax_automations/instead/documents/start_upload_worker.rb:25) declares:

```ruby
slug :tax_automations_instead_start_upload
sidekiq_throttle_as :tax_automations_instead
```

It includes `Sidekiq::Throttled::Worker`, selects the high-priority throttled queue, and reports API group `docs`.

**The throttle is registered in [config/initializers/sidekiq.rb](/Users/Shared/nav-ab/repo-master/config/initializers/sidekiq.rb:101)** with two one-minute thresholds, evaluated in this order:

1. **Per group, per connection:** key `instead:<group>:<connection_id>`.
2. **Whole app:** key `instead:app`.

Group-first ordering prevents a group-refused job from consuming the app budget.

Limits come from [config/settings.yml](/Users/Shared/nav-ab/repo-master/config/settings.yml:1817): `tax_automations.instead.rate_limit_groups` and `requests_per_minute`. Base defaults are **500 app requests/minute**, with group limits `docs: 5`, `entities: 50`, `agents: 10`, `webhooks: 50`, `scim: 50`, `default: 50`; production has its own app-budget override.
