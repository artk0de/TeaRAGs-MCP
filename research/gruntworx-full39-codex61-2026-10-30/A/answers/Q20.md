[`Documents::UpdateStatus`](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/documents/update_status.rb:10) accepts:

```ruby
UpdateStatus.call(user, system_actor, tax_automation_document_id,
  processing_status: :error,
  failure_reason: :encrypted
)
```

- `processing_status`: required String/Symbol in the **shared TD vocabulary**, already mapped by the provider adapter.
- `failure_reason`: optional shared reason; used **only for `error`**. `exceeded` sets its own reason through AASM.
- Only the **System actor** is authorized.
- This service updates processing status, not upload status.

It returns the send record on success, or:

| Failure | Code |
|---|---|
| Record missing | `not_found` |
| AASM disallows the transition | `unprocessable` |
| Invalid status or applied failure reason | `validation_error` |

The transition runs transactionally; broadcasting happens **after commit**. Reporting the current status again is a no-op transition but still schedules a broadcast.

`resource.id` identifies the **send record**; `document_id` identifies the original client document. Both state axes are included, and `failure_reason` may be `null`. The frame contains enum strings, with no localized messages, provider field or actor details.
