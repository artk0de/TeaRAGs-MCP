[`Instead::ExportAsync`](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/instead/export_async.rb:27) does the following:

1. Resolves the firm’s usable connection through `Registry.usable_connection_for(actor.firm)`.
2. Authorizes **`:read` on that connection** using `ConnectionPolicy.authorize!(user, actor, :read, connection)`.
3. Builds workflow arguments:

   ```ruby
   {
     connection_id: connection.id,
     tax_preparation_id: tax_preparation.id,
     tax_automation_document_ids: params[:tax_automation_documents].map(&:id)
   }
   ```

4. Starts `Instead::Documents::ExportAsyncWorkflow.perform_async_operation(user, actor, args)` and returns `async_result(async_operation)`.

Enqueueing happens **after the shared export transaction commits**, so a rolled-back send starts no workflow. The service makes no vendor HTTP call itself; send records remain `waiting` until workflow steps run.

The shared entry point has already checked export permissions; this adapter service additionally checks access to the connection.
