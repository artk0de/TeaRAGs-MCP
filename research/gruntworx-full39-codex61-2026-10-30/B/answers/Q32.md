Да, **`GruntWorx::Documents::ReconcileStatusesAsync` — реализация порта адаптером**.

Общий `Documents::ReconcileSweepWorker` выбирает кандидатов и вызывает:

```ruby
adapter::Documents::ReconcileStatusesAsync.call(
  owner.user,
  owner,
  connection,
  {tax_automation_document_ids:}
)
```

GruntWorx реализует этот контракт: запускает сверку указанных отправок по своему API и переводит результат в общие статусы TD.

То есть нейминг здесь уже задан портом и должен совпадать с `Instead::Documents::ReconcileStatusesAsync`. Новым механизмом общего слоя это не является.
