Под **маркером привязки** я имею в виду `FirmSettings.external_tenant_uuid` — сохранённый идентификатор аккаунта фирмы **у провайдера**.

Он отвечает на вопрос: «Это тот же внешний аккаунт, под которым мы уже отправляли документы?» Токены могут обновиться, сотрудник может смениться, но внешний аккаунт должен оставаться прежним, иначе сохранённые vendor ID могут стать недоступны.

У Instead это работает так:

1. При обмене authorization code клиент читает `firm_uuid` из ответа провайдера.
2. Адаптер передаёт его через временный атрибут `connection.external_tenant_uuid`.
3. Общий `Connections::Create` сравнивает его с постоянным значением в `FirmSettings`.

| Ситуация | Результат |
|---|---|
| Маркера ещё нет | Сохраняем полученный идентификатор |
| Идентификатор совпадает | Разрешаем подключение |
| Идентификатор отличается | Возвращаем `account_mismatch`, откатываем транзакцию и пытаемся отозвать новый grant |
| Провайдер не сообщил идентификатор | Пропускаем проверку; существующий маркер сохраняем |

**Когда привязка сбрасывается:**

- При явном `Connections::Disconnect`.
- При `Connections::DisconnectAll`.
- При выборе другого провайдера.
- При удалении `FirmSettings` вместе с фирмой.

Истечение или отзыв grant сами по себе маркер не сбрасывают: последующее переподключение должно восстановить доступ к тому же аккаунту. После явного отключения можно подключить другой.

Важные детали для GWX:

- Это ID внешнего **аккаунта/организации**, не налогоплательщика, контакта или отправки.
- Поле в БД имеет тип **UUID**. Числовой или произвольный строковый GWX account ID потребует изменения хранения.
- Привязка не уникальна между фирмами TD: несколько фирм могут подключиться к одному внешнему аккаунту.
- Если GWX не предоставляет стабильный account ID, текущая проверка не защищает от смены аккаунта.
