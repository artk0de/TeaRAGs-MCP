The shared base also chains subclass retry callbacks so they retain global rules. Throttled rescheduling resets retry count, so ten retries are **not a total wall-clock deadline**.

Sources: [shared base](/Users/Shared/nav-ab/repo-master/app/workers/tax_preparation/tax_automations/operation_worker.rb:9), [Instead base](/Users/Shared/nav-ab/repo-master/app/workers/tax_preparation/tax_automations/instead/operation_worker.rb:7).

**Concrete workers declare their own slug and opt into throttling**, for example:

```ruby
slug :tax_automations_instead_start_upload
sidekiq_options queue: :tax_preparation_tax_automations_high_throttled
sidekiq_throttle_as :tax_automations_instead
```

The Instead base does not automatically enable the throttle. Byte-transfer workers deliberately run outside it.

**Throttle configuration** is registered as `:tax_automations_instead` in [Sidekiq’s initializer](/Users/Shared/nav-ab/repo-master/config/initializers/sidekiq.rb:106), with two one-minute thresholds:

1. **Per API group, per connection:** limit from `Settings.tax_automations.instead.rate_limit_groups[group]`; key `instead:<group>:<connection_id>`.
2. **App-wide:** limit from `Settings.tax_automations.instead.requests_per_minute`; key `instead:app`.

The group threshold runs first to avoid charging the app budget for work already blocked by its group.

Limits are defined in [settings.yml](/Users/Shared/nav-ab/repo-master/config/settings.yml:1819), with [production overrides](/Users/Shared/nav-ab/repo-master/config/settings/production.yml:187). The separate `Instead::ExportOperationWorker` adds `step_only!` and marks affected uploads failed when retries are exhausted.
