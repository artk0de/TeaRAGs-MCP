[`Documents::UpdateStatus`](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/documents/update_status.rb:10) accepts:

```ruby
UpdateStatus.call(user, system_actor, tax_automation_document_id,
  processing_status: :error,
  failure_reason: :encrypted)
```

- `processing_status`: required string/symbol in the shared vocabulary: `sent`, `processing`, `processed`, `error`, `archived`, `exceeded`.
- `failure_reason`: optional shared reason, read only when the requested status is `error`. Entering `exceeded` sets its reason through AASM.
- Only a **System actor** is authorized. Adapters must translate vendor statuses first.
- It updates processing status, not upload status, and broadcasts **after commit**.
- Success returns the send record. Failures are `not_found`, `unprocessable` for an invalid transition, or `validation_error` for an invalid enum value.

[`BroadcastStatus`](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/documents/broadcast_status.rb:31) sends this frame to the firm’s `DocumentsChannel`:

```json
{
  "resource": {
    "id": 123,
    "document_id": 456,
    "processing_status": "error",
    "upload_status": "uploaded",
    "failure_reason": "encrypted"
  },
  "type": "tax_automation_document",
  "event": "status_changed"
}
```

`id` identifies the **send record**; `document_id` identifies the stored document. The frame contains enum strings and IDs, with no localized messages or vendor error text. `failure_reason` can be `null`.
