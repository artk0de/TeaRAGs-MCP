They use **`json-schema`**, locked at **6.2.0**, through `JSON::Validator.validate`.

[`TaxAutomationsHelpers`](/Users/Shared/nav-ab/repo-master/spec/support/tax_automations_helpers.rb:85) loads the vendor OpenAPI YAML and validates a payload against a named component:

```ruby
def conforms_to_contract?(schema_name, payload)
  JSON::Validator.validate(
    instead_contract.merge('$ref' => "#/components/schemas/#{schema_name}"),
    payload
  )
end
```

The whole OpenAPI document remains the schema root so internal `$ref`s resolve.

[Instead client specs](/Users/Shared/nav-ab/repo-master/spec/unit/tax_preparation/lib/tax_automations/instead/client_spec.rb:696) explicitly check:

| Fixture | Component schema |
|---|---|
| `entity.json` | `Entity` |
| `file.json` | `File` |
| `start_upload.json['Upload']` | `SignedUpload` |
| `token.json` | `TokenResponse` |

They also validate selected client results replayed from VCR, including entities, file metadata and mapped signed-upload targets.

**This is explicit schema validation in individual examples—not automatic validation of every mocked response.** The disconnected mock router has no contract-validation wrapper. Likewise, these checks validate component payloads, not the complete HTTP contract of paths, methods, headers and status codes.
