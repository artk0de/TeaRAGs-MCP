Based on the migrations, both tables have the standard `id` primary key plus these indexes and foreign keys.

**`tax_preparation_tax_automations_instead_connections`**

| Index | Columns | Constraint |
|---|---|---|
| `idx_ta_instead_connections_on_firm` | `firm_id` | **Unique** — one connection per firm |
| `idx_ta_instead_connections_on_refresh_expires_at` | `refresh_expires_at` | Partial: `WHERE status = 1` (`connected`) |

**No foreign keys.** `firm_id` is deliberately a soft reference because firm lifecycle crosses domain boundaries. The polymorphic `creator_type` / `creator_id` has no FK.

The original unique `(firm_id, creator_type, creator_id)` index was removed when connections became unique per firm.

**`tax_preparation_tax_automations_instead_documents`**

| Index | Columns | Constraint |
|---|---|---|
| `idx_ta_instead_documents_on_ta_document` | `tax_automation_document_id` | **Unique** |
| `idx_ta_instead_documents_on_entity` | `instead_entity_id` | Nonunique |
| `idx_ta_instead_documents_on_firm_external` | `firm_id, external_uuid` | **Unique**, where `external_uuid IS NOT NULL` |
| `idx_ta_instead_documents_on_external_uuid` | `external_uuid` | **Unique**, where `external_uuid IS NOT NULL` |

| Foreign key | References | Delete behavior |
|---|---|---|
| `tax_automation_document_id` | `tax_preparation_tax_automations_documents.id` | **CASCADE** |
| `instead_entity_id` | `tax_preparation_tax_automations_instead_entities.id` | Default; no cascade |
| `firm_id` | — | Soft reference, no FK |

The global unique `external_uuid` index supports webhook lookup without knowing the firm.
