The hierarchy is:

```text
Platform::Async::Operation::Worker
└─ TaxAutomations::OperationWorker
   └─ Instead::OperationWorker
      ├─ Instead::ExportOperationWorker
      │  ├─ Clients::CreateEntityWorker
      │  ├─ Documents::StartUploadWorker
      │  ├─ Documents::TransferBytesWorker
      │  └─ Documents::FinalizeUploadWorker
      └─ Webhooks::ProcessEventWorker
```

| Workers | Behavior |
|---|---|
| Create entity, start upload, finalize upload | Inherit `ExportOperationWorker`; workflow-only; high throttled queue; Instead throttle (`entities` or `docs` group) |
| Byte transfer | Also inherits `ExportOperationWorker`; high **unthrottled** queue because it transfers to storage, not Instead’s API |
| Webhook processing | Inherits `Instead::OperationWorker` directly; high unthrottled queue; no export-step file-failure callback |

All inherit the shared **10-retry default** and global retry rules.

When an export step exhausts retries, [`ExportOperationWorker`](/Users/Shared/nav-ab/repo-master/app/workers/tax_preparation/tax_automations/instead/export_operation_worker.rb:5):

- Runs inherited operation-failure handling first.
- Skips file updates if the operation is missing or canceled.
- Reads affected IDs through `Args#tax_automation_document_ids`: all send files for entity creation, one file for each upload step.
- Uses the terminal refusal’s mapped reason, or **`network_error` for any other exhausted exception**.
- Calls shared `Documents::FailUpload`.

[`FailUpload`](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/documents/fail_upload.rb:42) moves eligible uploads from `waiting`/`uploading` to `failed`, and processing to `error` or `exceeded` where permitted. Already `uploaded` or `failed` records stay unchanged. Status broadcasts run after commit.
