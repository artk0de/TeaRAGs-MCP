**It verifies the signed raw body, validates selected fields, and acknowledges accepted deliveries before asynchronous processing. There is no explicit event-ID deduplication.**

1. **Signature verification**
   - Requires `X-Instead-Signature-Algorithm: hmac-sha256`.
   - Computes HMAC-SHA256 over `"<timestamp>.<raw body>"` and compares securely.
   - Accepts timestamps within **±5 minutes**.
   - Tries both current and previous configured signing secrets.
   - Failed verification returns **401**.

2. **Payload validation**
   - Reads **body parameters only**, preventing unsigned query parameters from overriding signed fields.
   - Requires a supported event type, nonempty event ID, and UUID-shaped entity/resource IDs.
   - Permits selected nested data fields; accepts `IndexErrorReason` only as a token such as `password_required`.
   - Worker arguments additionally validate document index statuses; entity processing requires UUIDv7 event IDs and appropriate entity fields.

3. **Acknowledgement and routing**
   - Signed but invalid payloads are logged and return **200**.
   - Document events resolve the firm through the entity/file mapping; entity events resolve firms through the external account binding.
   - Unmatched deliveries, firms without an owner, and rejected worker arguments also receive **200** without processing.
   - Matched deliveries enqueue asynchronous operations, then return **200**. Unexpected exceptions can still produce an error response.

4. **Duplicate and stale deliveries**
   - No processed-event ledger or explicit deduplication keyed by `event_id` exists in this path.
   - Document handlers make repeated statuses a no-op and refuse backward transitions.
   - Entity handlers extract occurrence time from the UUIDv7 event ID and ignore events older than `synced_at`. Equal-time repeats can be applied again.
