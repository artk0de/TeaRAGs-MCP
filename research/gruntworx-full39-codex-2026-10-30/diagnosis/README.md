# Диагностика повторных инструкций и исследований

Это дополнение разбирает **уже завершённую** пару A/B. Новых модельных запусков, обращений к upstream, product tests или изменений плагина здесь нет. Исходные raw streams, отчёт, метрики и `../inventory.sha256` сохранены без изменений. Пять отклонённых proxy ответов по-прежнему ограничивают причинную интерпретацию: один parser defect подтверждён, исходные payload четырёх текстовых отклонений неизвестны.

## Что действительно повторялось

- `tea-rags://guide/navigation` прочитан **23 раза**, каждый раз доставлено одинаковое тело **19 668 символов**: суммарно **452 364 символа**. На одном Q03 пришлись четыре таких чтения — ещё до первой compaction. Это повторная доставка одинаковой справки, а не 23 новых исследования кода.
- Одна и та же canonical `explore/SKILL.md` прочитана пятью идентичными успешными `cat` в Q01–Q05 до первой compaction. В Q15 есть ещё одна попытка открыть Explore по выдуманному пути в `superpowers`; она завершилась `No such file or directory`, а не доставкой инструкций. Сам по себе повтор после compaction не доказывает избыточность: содержимое могло не сохраниться в кратком контексте.
- В Q01 и Q32 выполнен `ALL_TOOLS.filter(...)` с печатью **полных объектов**, а не списка имён. Каждый вывод — **40 821 символ**, включая notice о truncation исходного вывода в 34 620 tokens. Всего повторно доставлено 81 642 символа tool metadata. Это наблюдаемый footgun загрузки инструментов; выводить `.map(t => t.name)` и затем запрашивать только нужное описание — конкретный способ избежать такого dump, но эффект изменения этим экспериментом не измерялся.

Точные вопросы, call IDs и счётчики находятся в [evidence-A.json](evidence-A.json). Эти объёмы — символы инструментального контекста; их нельзя складывать с model output tokens или без tokenizer переводить в стоимость.

Пики A в Q05 и Q32 относятся к **самим compaction requests**, определённым по активному интервалу `contextCompaction`. Падение последнего input в этих строках отражает уже сокращённый контекст, а не отсутствие предыдущего роста. У B за все 39 вопросов максимум **168 313** в Q39 и ни одной compaction. Это наблюдаемая разница давления на контекст в данной guarded паре, а не доказательство, что конкретное правило единолично вызвало compaction.

Если исключить compaction requests, максимальный обычный input A — **244 838** в Q31; в Q05 до первой compaction обычный запрос уже достиг **244 530**. Следовательно, высокий input не объясняется только служебным запросом summarization.

Для выбранных снимков доступна численная attribution: `usageMetadata.metadata.attribution.items` сопоставляется с raw item IDs. В каждом запросе сумма attributed input в точности совпала с `usage.inputTokens`. На пике Q05 из 244 711 tokens:

| Наблюдаемый retained context | Input tokens |
|---|---:|
| Чистые MCP source/search/graph tool results | 80 918 |
| Shell observations, включая inventories | 18 004 |
| Skill и reference outputs | 30 752 |
| Navigation outputs: семь retained items | 34 083 |
| Один полный tool-metadata dump | 11 078 |
| Opaque reasoning-state items, только тип и число | 36 991 |

Остальное — developer/user/assistant context, определения и история tool calls, другие references и явно unmapped items; полный баланс есть в JSON. Tool outputs классифицированы только при однозначном wrapper request. Смешанные результаты не приписываются произвольно исходному коду или справке. На пике Q32 остаются **50 120 tokens unclassified tool outputs** и **15 187 unmapped tokens**, поэтому точную долю source против references для этого пика заявлять нельзя.

Это состав **удержанного входа**, включая cached tokens, а не количество уникальных новых чтений и не оценка удаляемого мусора. Reasoning summary/encrypted contents не изучались; использованы только типы и числовая attribution. [context_growth.py](context_growth.py) выполняет один offline проход по имеющемуся gzip, без модели, upstream или повторного исследования кода.

## Hooks: много запусков, мало текстовых добавлений

Зафиксировано **825 завершений hooks**: SessionStart12, UserPromptSubmit117, PreToolUse291, PostToolUse405. Сумма сообщённых durations — **68 622 мс**. Это сумма длительностей, а не отдельная непересекающаяся часть session wall: параллельные операции и scheduling не дают такого разложения.

Только **48 завершений** содержат непустой текст: routing39, core3, tools3, prime3. Полный core не вставлялся 825 раз. В непустых outputs нет reread-nudge; запись не показывает, чтобы такой nudge остановил наблюдаемые повторные чтения справки. Это не доказывает, что ledger не обновлял состояние или бесполезен для других типов чтений.

Три появления core/tools/prime согласуются с началом сессии и двумя compactions. Повторная установка необходимых правил после смены контекста может быть оправданной; её нельзя автоматически приравнивать к четырём одинаковым чтениям navigation внутри Q03.

Однако разность `wall − tool durations` **не является** измерением чистого thinking: там могут быть ожидание провайдера, сеть, streaming, hooks, compaction и другие накладные расходы. ## Объём `find_symbol` и границы вывода

В 95 вызовах `find_symbol` не наблюдается `batchNotice`. Дополнительная агрегация относит **178 747 из 355 759 content characters** к headers, около 50.2%. Это состав доставленного контекста, **не доказательство**, что половина его бесполезна: headers могут содержать необходимые объявления, константы или контракты. В этом полном прогоне нельзя объяснять расходы непроявившейся budget-defer ошибкой или обещать экономию в 50% удалением headers.

## Воспроизводимость и ограничения

### Официальные источники и проверка новой инструкции

Parent прочитал [Rethinking skills and prompts for GPT‑6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra), [Build skills](https://developers.openai.com/plugins/build/skills) и [Skills concepts](https://developers.openai.com/plugins/concepts/skills). Важные для этих наблюдений рекомендации: краткое точное описание активации, небольшой router с условной загрузкой references, чтение контекста по потребности задачи и отсутствие фиксированного маршрута там, где он не нужен для корректности. Проверять следует также неактивацию и нежелательные outputs. В этом дополнении сетевые запросы не повторялись. Рекомендации из статьи о конкретной модели Astra не являются доказательством эффекта на использованной здесь Luna.

Для изменённой parent инструкции `CODEX_SKILL_LOADING` выполнен отдельный **статический review инструкции**, а не поведенческий запуск: follow-up с сохранённым контекстом → без повторного чтения; новый workflow → выбранный `SKILL.md` и релевантный reference; потерянный при compaction контекст → повторно открыть только нужное; неизвестный tool → сначала имена, затем нужное описание. Review не нашёл обязательного reread или требования следовать незагруженным инструкциям в этих четырёх сценариях. Частично сохранённый контекст и непрозрачные tool names остаются областью суждения агента. Это **не behavioral/performance green** и не измеренная экономия.

[analyze.py](analyze.py) читает только существующий gzip stream и дедуплицирует response IDs и item IDs. Производные JSON на 419/121 КБ оставлены в `.tmp`; здесь сохранены лишь компактные [A](evidence-A.json) и [B](evidence-B.json). Supplemental payload/metadata агрегаты явно отделены в evidence от счётчиков основного скрипта.

[reproduce_proxy.py](reproduce_proxy.py) содержит синтетические offline fixtures для list/dict и plain-text обработчиков. Они воспроизводят поведение parser, а не восстанавливают отсутствующие исходные четыре payload. В этом дополнении fixture не запускался повторно.

Наблюдения обосновывают фокус на повторной доставке неизменной справки, полном metadata dump и количестве модельных шагов. Они не доказывают, сколько времени сэкономит конкретный новый cache или новая формулировка правил. Новая версия плагина и её эффект требуют отдельной проверки по отдельному разрешению пользователя; данная завершённая пара не перезапускалась.
