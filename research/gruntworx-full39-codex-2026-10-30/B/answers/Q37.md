The application defines **eight tax-automation metrics** in `config/initializers/yabeda.rb`:

| Metric | Type | Tags | What it measures |
|---|---|---|---|
| `requests_duration` | Histogram | `vendor`, `operation` | Time for vendor API calls, token operations, and signed-target byte transfers. |
| `failed_requests_total` | Counter | `vendor`, `operation`, `reason` | Failed vendor requests, categorized by HTTP status, network error, lock timeout, invalid grant, or no principal. |
| `rate_limit_remaining` | Gauge | `vendor`, `group` | Requests remaining in a vendor’s rate-limit window, when reported in response headers. |
| `rate_limit_reset_seconds` | Gauge | `vendor`, `group` | Seconds until that window resets. |
| `installation_changes_total` | Counter | `vendor`, `change` | Connections installed or uninstalled. |
| `reconciled_documents_total` | Counter | `vendor`, `processing_status` | Sends whose status reconciliation changed based on a vendor read. |
| `entity_matches_total` | Counter | `vendor`, `outcome` | Results of matching a taxpayer to a vendor entity. |
| `installations` | Gauge | `vendor` | Current vendor connections that have not ended. |
| `stale_sends` | Gauge | `vendor` | Uploaded sends past their reconciliation window that are still awaiting vendor status. |

The last two are populated by a periodic Sidekiq collector and cached for 60 seconds. The registry runs that collector for each registered adapter.
