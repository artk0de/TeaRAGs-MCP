`Instead::ExportAsync` resolves the firm’s usable connection, then authorizes the actor to **read that connection** via `ConnectionPolicy`. If authorized, it takes the IDs of the send records the shared port created and starts `Instead::Documents::ExportAsyncWorkflow` with the connection ID, tax-preparation ID, and send-record IDs. The operation is queued after the shared send transaction commits, so a rollback queues nothing. Records remain `waiting` until the workflow runs.

The workflow finds or links an existing Instead entity, or creates one if needed, then starts a separate upload chain for each file. That keeps a refusal on one file from holding up the others.
