Что уже следует из кода:

- **Регистрация адаптера** — в `TaxPreparation::TaxAutomations::Registry::ADAPTERS`; сейчас зарегистрирован только Instead. Для провайдеров можно задать feature flag в `FEATURE_FLAGS`.
- **Контракт namespace адаптера** — как минимум `Connection` с моделью соединения и `Client`, включающий `TokenRefreshable`; также namespace предоставляет сервисы, которые вызывают общие порты. Реестр выбирает адаптер по провайдеру фирмы или по классу connection.
- **Capability passport** — `Connection.capabilities`: декларация возможностей вендора без привязки к конкретной записи соединения. Сейчас паспорт описывает условия для каждого return type — принимаемые форматы и максимальный размер файла — и поддерживаемые налоговые годы. Контракт проверяется при вызове; отсутствующие или некорректные значения должны приводить к ошибке.
- **Данные и состояние** — общие настройки фирмы хранят выбранного провайдера; соединения принадлежат адаптерам. Реестр различает сохраненное соединение и пригодное для отправки, а также может получить соединения всех провайдеров по `firm_id`. Для отправок важно сохранять провайдера в момент создания: настройка фирмы может измениться.
