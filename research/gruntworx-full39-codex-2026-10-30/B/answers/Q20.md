The shared status-update service accepts the send record ID and:

- `processing_status` — required; a shared status (`sent`, `processing`, `processed`, `error`, `archived`, or `exceeded`). The adapter must translate the vendor’s status into this vocabulary.
- `failure_reason` — optional; a shared reason, used only when `processing_status` is `error`.

The call must use a `System` actor authorized to update status. The service rejects unknown statuses or reasons, missing records, and transitions the state machine won’t allow. It does **not** accept upload status; that is updated by the upload workflow.

After commit, the broadcast sends this frame to the firm’s tax-automation documents channel:

```json
{
  "resource": {
    "id": 123,
    "document_id": 456,
    "processing_status": "processed",
    "upload_status": "uploaded",
    "failure_reason": null
  },
  "type": "tax_automation_document",
  "event": "status_changed"
}
```

The IDs and enum values are sent as-is; there’s no localized message in the frame.
