### HTTP status → client error

The shared `BaseClient` middleware raises a typed error for every HTTP response with status `400+`:

| Status | Error |
|---|---|
| 400 | `BadRequestError` |
| 401 | `UnauthorizedError` |
| 403 | `ForbiddenError` |
| 404 | `NotFoundError` |
| 422 | `UnprocessableEntityError` |
| 423 | `LockedError` |
| 429 | `RateLimitedError` |
| 500 | `ServerError` |
| 503 | `ServiceUnavailableError` |
| Other 5xx | `ServerError` |
| Other 4xx | `RequestError` |

A vendor adapter may classify a response body as a more specific shared or vendor-specific error—for example, quota exceeded or insufficient scope. The client also extracts a vendor message where possible and retains the response body, status, and headers on the error. `RateLimitedError` can parse `Retry-After` as seconds or an HTTP date.

### Metrics

The shared client emits:

- **`requests_duration`** — request time, tagged by vendor and operation (`api_request`, `upload_transfer`, and token operations such as `token_refresh`).
- **`failed_requests_total`** — failures tagged by vendor, operation, and reason, including HTTP status, network error class, lock timeout, and invalid grant.
- **`rate_limit_remaining`** and **`rate_limit_reset_seconds`** — when a response carries the vendor’s rate-limit headers, tagged by vendor and API group.

### Terminal refusals → send failure reason

The refusal helper marks affected send records failed. Its explicit mappings are:

| Refusal | Failure reason |
|---|---|
| Quota exceeded | `exceeded` |
| Insufficient scope | `unauthorized` |
| Invalid/rejected grant | `unauthorized` |
| HTTP 401 | `unauthorized` |
| Policy refusal | `forbidden` |

Other terminal vendor refusals—such as `403` without the insufficient-scope classification, `404`, `400`, `422`, `423`, or unusable upload targets—fall back to **`api_error`**. A policy refusal or invalid grant is also re-raised after marking the files failed; an invalid grant triggers grant verification. Transient network and server failures follow the retry path instead of this terminal refusal mapping.
