`UpdateStatus.call(user, actor, tax_automation_document_id, params)` accepts:

- `processing_status`: one of `sent`, `processing`, `processed`, `error`, `archived`, or `exceeded`.
- `failure_reason`: optional; used only when `processing_status` is `error`. Allowed values are `unexpected`, `no_active_connection`, `network_error`, `unauthorized`, `api_error`, `exceeded`, `forbidden`, and `encrypted`.

The shared status-update service is authorized for a system actor. It rejects unknown status/reason values and unreachable transitions; reporting the record’s current status again is a no-op. After a successful update, it broadcasts after the transaction commits ([UpdateStatus](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/documents/update_status.rb:10), [status vocabularies](/Users/Shared/nav-ab/repo-master/app/models/tax_preparation/tax_automations/document.rb:11)).

The firm’s frontend stream receives this frame:

```json
{
  "resource": {
    "id": "<send record ID>",
    "document_id": "<TD document ID>",
    "processing_status": "<status>",
    "upload_status": "<status>",
    "failure_reason": "<reason or null>"
  },
  "type": "tax_automation_document",
  "event": "status_changed"
}
```

It’s broadcast to the firm’s `TaxAutomations::DocumentsChannel`; the frame contains IDs and enum values, not localized text ([BroadcastStatus](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/documents/broadcast_status.rb:21)).
