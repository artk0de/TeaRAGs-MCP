**Verification:** TaxDome checks `X-Instead-Signature`, the declared algorithm (`hmac-sha256`), and a timestamp within **±5 minutes**. It computes HMAC-SHA256 over `timestamp.raw_body`, compares it securely, and accepts either the current or previous signing secret during key rotation. An invalid signature gets **401 Unauthorized** ([signature verifier](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/instead/webhooks/signature.rb:10), [endpoint](/Users/Shared/nav-ab/repo-master/app/controllers/tax_preparation/webhooks/tax_automations/instead/events_controller.rb:6)).

**Validation and acknowledgement:** The endpoint validates the signed request body: event type must be recognized, event ID must be present, entity and resource IDs must be UUIDs, and document indexing events must carry a recognized index status. Invalid payloads are logged and **acknowledged with 200**, so the vendor is not asked to retry them. Valid events are queued asynchronously and also get **200**; unmatched events are logged and dropped with 200. Invalid signatures are the case that gets 401. Query parameters cannot override the signed body ([event form](/Users/Shared/nav-ab/repo-master/app/forms/tax_preparation/webhooks/tax_automations/instead/event_form.rb:17)).

**Deduplication:** There is **no delivery-ID deduplication at the endpoint or enqueue boundary**. The `event_id` is carried into the async worker, but each valid delivery can create a new async operation; there is no webhook inbox or unique-event check in this path ([event enqueue](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/instead/webhooks/process_event_async.rb:83), [async operation enqueue](/Users/Shared/nav-ab/repo-master/app/services/tech/async/enqueue.rb:40)).
