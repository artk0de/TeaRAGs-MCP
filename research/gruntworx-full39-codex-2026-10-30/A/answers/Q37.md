The `tax_automations` Yabeda group defines these application metrics in [config/initializers/yabeda.rb](/Users/Shared/nav-ab/repo-master/config/initializers/yabeda.rb:31):

| Metric | Type | Tags | What it measures |
|---|---|---|---|
| `requests_duration` | Histogram, seconds | `vendor`, `operation` | Duration of vendor API calls, OAuth operations, and signed upload transfers. |
| `failed_requests_total` | Counter | `vendor`, `operation`, `reason` | Failed vendor requests and token operations. Reasons include HTTP errors, network errors, lock timeouts, invalid grants, and missing principals. |
| `rate_limit_remaining` | Gauge | `vendor`, `group` | Requests left in the vendor’s rate-limit window. |
| `rate_limit_reset_seconds` | Gauge | `vendor`, `group` | Seconds until that rate-limit window resets. |
| `installation_changes_total` | Counter | `vendor`, `change` | Connections installed or uninstalled. |
| `reconciled_documents_total` | Counter | `vendor`, `processing_status` | Sends whose status reconciliation read from the vendor; unchanged statuses are not counted. |
| `entity_matches_total` | Counter | `vendor`, `outcome` | Taxpayer-to-vendor-entity matching results: match, swapped-name match, namesakes, swapped namesakes, or no match. |
| `installations` | Gauge | `vendor` | Current vendor connections not ended by their firm. |
| `stale_sends` | Gauge | `vendor` | Sends still awaiting vendor status past the reconciliation window. |

The last two gauges are collected periodically in Sidekiq processes. The rate-limit gauges are populated from vendor response headers. Failed token refreshes can increment `failed_requests_total` for both `token_refresh` and the `api_request` that needed it, so the counts should be read by operation.
