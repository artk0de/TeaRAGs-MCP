The shared `BaseClient` uses the same HTTP error mapping and instrumentation for each provider; provider clients can refine an error using identifiers in the response body.

**HTTP errors:** Responses below 400 pass through. The mapped statuses are `400` BadRequest, `401` Unauthorized, `403` Forbidden, `404` NotFound, `422` UnprocessableEntity, `423` Locked, `429` RateLimited, `500` ServerError, and `503` ServiceUnavailable. An unmapped 5xx becomes ServerError; another unmapped 4xx becomes a generic RequestError. Errors retain the response code, body, and headers. A 401 triggers the auth retry and forced-refresh path; network connection, timeout, and SSL failures become NetworkError. See [BaseClient’s error map](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/base_client.rb:132) and [status handling](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/base_client.rb:177).

**Metrics:**

- `requests_duration` histogram, tagged by `vendor` and `operation` (`api_request`, `token_refresh`, or `upload_transfer`).
- `failed_requests_total` counter, tagged by `vendor`, `operation`, and `reason`—for example `HTTP_ERROR: 403`, `NETWORK_ERROR: Faraday::TimeoutError`, `INVALID_GRANT`, or `LOCK_TIMEOUT`.
- `rate_limit_remaining` and `rate_limit_reset_seconds` gauges, tagged by `vendor` and API `group`, when the response includes `X-RateLimit-Remaining` or `X-RateLimit-Reset`.

The rate-limit reset header is converted from an epoch to seconds remaining, clamped at zero. See [metric instrumentation](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/base_client.rb:418) and [rate-limit recording](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/base_client.rb:216).

**Refusal reasons:** Terminal refusals end the affected send and map to TD’s failure-reason vocabulary. `QuotaExceededError` → `exceeded`; insufficient scope, invalid grant, and unauthorized → `unauthorized`; policy refusal → `forbidden`. Other terminal refusals default to `api_error`. In particular, a plain vendor `ForbiddenError` defaults to `api_error`; the `forbidden` mapping is for `AbstractPolicy::PolicyError`. See [RefusalsHelper](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/refusals_helper.rb:20).

A provider may refine a status using its own error identifiers. For example, Instead maps `USAGE_LIMIT_EXCEEDED` to `QuotaExceededError` and `FORBIDDEN_INSUFFICIENT_SCOPE` to `InsufficientScopeError` ([Instead client](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/instead/client.rb:44)).
