Ниже — полный маппинг **на границе интеграции**, которую можно подтвердить по текущему коду и обсуждённым требованиям. Точных названий полей GWX API в доступных мне материалах сейчас нет, поэтому не выдаю предполагаемые ключи GWX за подтверждённые.

| Область | TaxDome (TD) | GruntWorx (GWX) | Правило маппинга / статус |
|---|---|---|---|
| Провайдер | Провайдер налоговой автоматизации, выбранный для фирмы | GruntWorx | GWX подключается как отдельный provider adapter. Его конкретный идентификатор и структура регистрации требуют сверки со спецификацией. |
| Подключение | Фирменная connection-запись провайдера | Учётная запись или контекст доступа GWX | Маппинг данных авторизации пока не определён. Предыдущий план — начать с mock-транспорта, а не считать наличие OAuth обязательным. |
| Возможности провайдера | Capability passport: условия по типам деклараций, допустимым форматам и размеру файлов; поддерживаемые налоговые годы | Соответствующие ограничения и поддержка GWX | Adapter переводит сведения GWX в TD-контракт. TD сериализует возможности как `returnTypes` и `taxYears`. Точные значения GWX нужно взять из документации. |
| Фирма | TD firm, владелец подключения и настроек подготовки налогов | Клиентский аккаунт / контекст фирмы в GWX | Связь GWX-аккаунта с TD firm задаётся на уровне connection; конкретный GWX-идентификатор не подтверждён. |
| Клиент / налогоплательщик | TD client | Налогоплательщик или клиентская запись GWX | Требуется явное сопоставление существующего клиента, чтобы не создавать дубликаты. Поля и приоритеты матчинга нужно закрепить в контракте; автоматическое сопоставление по одному имени не следует считать безопасным. |
| Налоговый идентификатор | Настройка TD для business tax identifier; значение EIN может передаваться при соответствующих условиях | Идентификатор налогоплательщика GWX | Для бизнес-декларации TD передаёт EIN, если включено сохранение идентификатора и значение заполнено. Точное поле GWX не установлено. |
| Тип декларации | TD `return_type` | Тип/продукт декларации GWX | Adapter нормализует тип GWX в тип, который понимает TD capability passport. Таблица кодов TD↔GWX ещё требует подтверждения по GWX docs. |
| Налоговый год | TD `tax_year` / поддерживаемые годы клиента и провайдера | Налоговый год GWX | Передавать год явно; проверять его по `supported_tax_years` провайдера. |
| Исходные документы | TD tax-automation documents и вложенные файлы клиентских документов | Исходные документы, отправляемые на обработку | Передавать содержимое файлов и необходимые метаданные. Ограничения формата и размера проверять по возможностям провайдера для выбранного типа декларации. |
| Результаты обработки | TD client documents | Результатные файлы GWX | Каждый полученный результат сохранять как документ TD и связывать с нужными клиентом и tax-automation job. GWX возвращает PDF, XLS и XLSM; для XLSM действует отдельное ограничение preview, см. примечание ниже. |
| Статус обработки | TD-состояние tax-automation операции | Статус задания GWX | Нужна нормализация статусов GWX в TD-состояния. Полный перечень GWX-статусов и соответствия пока не подтверждены. |
| Ошибки | TD failure reason / ошибка операции | Ошибки API, обработки, авторизации или файла GWX | Adapter должен переводить vendor-specific причины в общий словарь TD и сохранять исходную причину для диагностики. Таблица кодов требует документации GWX. |
| Повторная сверка | TD job и сохранённые результаты | Состояние задания и результат в GWX | Нужен способ обнаружить завершение или результат, если webhook потерян; конкретный endpoint и поля сверки не подтверждены. |
| Подпись / URL файла | TD скачивание или вложение файла | Ссылка GWX на результат, возможно временная | При mock-реализации нужно проверять скачивание результата до истечения URL и не полагаться на долгоживущую ссылку. Формат и подпись URL требуют сверки с GWX. |

Что подтверждается кодом TD: capability passport собирается на уровне класса connection, так как возможности описывают провайдера, а не отдельную запись подключения; паспорт содержит условия по типам деклараций и поддерживаемые годы. См. [HasCapabilities](/Users/Shared/nav-ab/repo-master/app/models/tax_preparation/tax_automations/has_capabilities.rb:3), [реестр провайдеров](/Users/Shared/nav-ab/repo-master/app/lib/tax_preparation/tax_automations/registry.rb:104) и [сериализатор connection](/Users/Shared/nav-ab/repo-master/app/serializers/tax_preparation/base/tax_automations/connection_serializer.rb:57).

Для результатов есть отдельный нюанс: TD разрешает сохранить `.xlsm` по проверке расширения, но не включает его в список расширений, пригодных для штатного preview; в настройке preview перечислены `xls` и `xlsx`, но не `xlsm` ([settings.yml](/Users/Shared/nav-ab/repo-master/config/settings.yml:1098)).

Чтобы превратить эту таблицу в подтверждённую таблицу **GWX-поле → TD-поле**, нужны названия и типы полей из документации GWX для клиента, задания, статусов, ошибок и файлов.
