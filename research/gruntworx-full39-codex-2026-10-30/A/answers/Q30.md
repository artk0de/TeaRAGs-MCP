- **Firms:** no UUID column. The `firms` table has no `uid` or `uuid` field in its definition, and I found no migration adding one ([table definition](/Users/Shared/nav-ab/repo-master/db/migrate/20241228010533_init_schema.rb:1567)).
- **Contacts:** yes. The column is named `uid` and has PostgreSQL type `uuid`; it defaults to `gen_random_uuid()`.
- **Client accounts:** these are stored in the `clients` table, which also has a UUID-typed `uid` with the same default. There is no standalone `accounts` table for client accounts.

The `uid` columns were added to `contacts` and `clients` in [this migration](/Users/Shared/nav-ab/repo-master/db/migrate/20260511100000_add_uid_to_contacts_and_clients.rb:4), with defaults added [here](/Users/Shared/nav-ab/repo-master/db/migrate/20260511105000_set_default_uid_for_contacts_and_clients.rb:4). So contacts and client accounts have a stable UUID-style identifier; firms do not.
