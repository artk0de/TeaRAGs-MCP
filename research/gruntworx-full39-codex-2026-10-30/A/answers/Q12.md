The contact merge runs TaxDome’s tax-automation merge service. It **reassigns or consolidates the TaxDome records for sent files**; it does not send those files again.

For each source tax-preparation record, TD looks for a record with the same firm, client account, tax year, and surviving contact. If none exists, it repoints the existing record to that contact. If one exists, TD moves the source’s tax-automation document records to it, except where the survivor already has a record for the same **document, provider, and return type**. In that duplicate case, the source record is left behind and removed when the source tax-preparation record is destroyed ([merge service](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/tax_preparations/merge_for_contact.rb:32)).

The configured provider’s adapter also gets a contact-merge call. For Instead, TD reassigns provider-document records to a matching entity for the surviving contact, or reassigns the entity itself when there is no match. When the source entity was created by TD, its local record is destroyed; when it came from Instead, TD unlinks it locally ([Instead merge](/Users/Shared/nav-ab/repo-master/app/services/tax_preparation/tax_automations/instead/merge_for_contact.rb:29)).

So TD updates its associations and records for the merge. The implementation shown does not issue a request to resend files; the provider-specific details are handled by the adapter.
