Вот индексы и внешние ключи двух таблиц.

**`tax_preparation_tax_automations_instead_connections`**

- Уникальный индекс по `firm_id` — не более одного подключения Instead на фирму; одновременно обслуживает поиск подключений по фирме.
- FK нет: `firm_id` — мягкая ссылка, поскольку фирма находится в другом кластере и удаление обрабатывается через событие `destroyed`.
- Полиморфные `actor_type` / `actor_id` FK также не имеют.
- Частичный индекс по `refresh_expires_at` для строк со `status = 1` (`connected`), чтобы находить подключения для продления токена.

**`tax_preparation_tax_automations_instead_documents`**

- Уникальный индекс по `tax_automation_document_id`: одна запись Instead на документ TaxDome.
- Обычный индекс по `instead_entity_id`.
- Частичный уникальный индекс по паре `firm_id, external_uuid`, когда `external_uuid IS NOT NULL`.
- Ещё один частичный уникальный индекс только по `external_uuid`, когда он задан. Он обслуживает поиск по UUID из webhook, где фирма в событии не передаётся.
- FK `tax_automation_document_id` → `tax_preparation_tax_automations_documents.id` с `ON DELETE CASCADE`.
- FK `instead_entity_id` → `tax_preparation_tax_automations_instead_entities.id`.
- FK на `firm_id` нет: это тоже мягкая ссылка.

У документов оба поля ссылок (`tax_automation_document_id` и `instead_entity_id`) обязательны.
